ClawMoat vs Lakera Guard

Lakera Guard is a hosted API for LLM runtime security. ClawMoat is a self-hosted, zero-dependency agent firewall. Different architectures, different trade-offs.

TL;DR: Choose Lakera if you want ML-powered detection via an API and have budget for enterprise sales. Choose ClawMoat if you want self-hosted, transparent pricing, supply chain protection, and zero vendor lock-in.

Architecture

Lakera is a cloud API. You send prompts to their endpoint, they return a risk score. Your data leaves your machine. Latency depends on network. Requires an API key and account.

ClawMoat runs entirely local. npm install, import, done. Nothing leaves your machine. Zero network calls. Zero auth. Zero dependencies.

Detection Approach

Lakera uses ML models trained on their proprietary dataset. This means better generalization for novel attacks, but it's a black box — you can't inspect or customize the detection logic.

ClawMoat uses pattern-based detection with 13 prompt injection patterns, 15+ supply chain indicators, and 6 insider threat detectors. It's transparent — you can read every pattern, add your own, and understand exactly why something was flagged.

What ClawMoat Has That Lakera Doesn't

  • Host-level protection — forbidden zones, dangerous command blocking, 4 permission tiers
  • Supply chain detection — real-time indicators for TeamPCP, CanisterWorm, compromised packages
  • Insider threat detection — 6 behavioral detectors based on Anthropic's agentic misalignment research
  • Network egress logging — tracks outbound connections from agents
  • Inter-agent message scanning — detects attacks between cooperating agents
  • Zero dependencies — no supply chain risk from the security tool itself
  • Transparent pricing — $0 / $29 / $149 on the website vs "Let's chat"

What Lakera Has That ClawMoat Doesn't

  • ML-powered detection — better at catching novel/creative prompt injections
  • PII detection and redaction — dedicated PII scanner with entity recognition
  • Enterprise SSO/RBAC — built for large orgs
  • Managed infrastructure — no self-hosting needed
  • Proven at scale — used by Dropbox and other large companies
