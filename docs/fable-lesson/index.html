Jailbreak resistance is not a security boundary.

Anthropic says perfect jailbreak resistance is probably not possible today. That should change how people think about agent security.

Buy the agent seatbeltRequest blast-radius reviewSee the attack demo

The practical lesson is not subtle.

Anthropic says it used strong model safeguards, thousands of hours of red teaming, monitoring, and data retention. It still says perfect jailbreak resistance is probably not possible.

That is not an indictment of Anthropic. It is a warning about the boundary.

A jailbreak against a chatbot is a bad answer.
A jailbreak against an agent is a tool-use incident.

If your agent can read repos, run shell commands, use MCP tools, access Gmail, touch credentials, browse the web, or keep working in the background, the security boundary cannot just be "the model will refuse."

What changes when the model has tools?

A chatbot can say something wrong. A tool-enabled agent can take an action. It can read a private file, call a shell command, post to GitHub, message a customer, touch a browser session, or send data to a network endpoint.

That means agent security needs runtime containment, not only prompt filtering.

Model safeguard

Tries to make the model refuse unsafe instructions.

Runtime containment

Controls what the agent can touch even when the model gets tricked.
